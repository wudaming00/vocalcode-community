## 验证

**自动化**：全工作区 Rust 测试（legacy / community 两种配置）、两种配置 clippy `-D warnings`、`cargo fmt --check`、前端 10 个 node 合约测试文件、页面脚本 `node --check`。新增约 60 个测试，其中一批直接取自真实识别输出（见下）。

**真实模型回放**：`vocalcode-platform/examples/writing_replay.rs`，Windows 自带 TTS 生成中英文 WAV → 真实 SenseVoice → 生产引擎 + 全部写作规则 → 内存注入器。暴露出两个理想化假设并已修正：SenseVoice 英文在停顿处常常不打句号但会把下一句首字母大写；中文「删掉上一句」会被连到前一句上。

**装进本机真实使用**（legacy 1.3.1 身份，数据目录不变）：
- 通过 UI 自动化在真实窗口里操作并截图：写作页、试一试（英 / 中）、快捷键页、设置页、历史复查、首页 Insights、改写草稿的翻译与自定义指令。
- 真声学回路：扬声器播放 TTS → C920 麦克风 → 注入 X2（用户自己的说话键）→ 真实 App → 自建测试输入框。换行（多行粘贴）、删掉上一句、列表、回车发送、双击免提都在这条链路上跑通过；外放识别会偶尔听错（「换行」→「换」、「第三，」→「第三5」），属识别误差。
- 静音：另起进程播放不可闻的正弦波，按住说话时该会话 `GetMute()` = true，松开后恢复 false。
- 本地 Ollama `qwen2.5:7b-instruct`（CPU）：中译英保留 1200 / 12000 USD 与两处否定；自定义指令「改短一点，语气更友好」约 8 s 出候选。

实测中发现并修复的真 bug：写作页自己的中文示例「你好，换行，…。删掉上一句。…」会把问候语一起删掉（撤回先于换行执行，看不到换行边界）。

## 语音语料发布测试（`packaging/voice-corpus/`）

`python packaging/voice-corpus/run.py --models <模型目录>`：生成 → 回放 → 打分，一条命令。

- **语料**：44 个用例（普通口述 10、命令 5、撤回 3、列表 4、代码词 4、回车 2、风格 3、语气词 2、片段 2、防误触 9）× 30 个声音（Edge 神经语音 12，含美/英/澳/印口音；Fish Official 16；Windows SAPI 2），再加噪声、1.25 倍速、低音量三种变体，共 1072 段。音频不入库（`target/voice-corpus/`，按声音 + 句子哈希缓存）；Fish 只用官方声音，不用社区克隆声音。
- **回放**：`vocalcode-app` 里被 `#[ignore]` 的 `voice_corpus` 测试。每段走生产路径：`models::build_asr`、该路线的清理链、带语音门的推理线程（含停顿处的后台预解码）、内置词典、片段、Engine 的逐句设置；虚拟 80 ms 时钟。每段跑两遍：规则全开 / 全关。四条路线：zh SenseVoice、en SenseVoice、en Qwen3-ASR 0.6B、en Parakeet TDT v3。
- **闸门**（`score.py`，全部满足才返回 0）：G1 防误触用例在任何声音、变体下一条规则都不许触发；G2 规则全关时什么都不发送、普通文字逐字节相同；G3 识别结果里已经有命令词（且整句词错误率 ≤ 50%）、输出却不对（算我们的 bug）≤ 2%；G4 干净神经语音上功能成功率每条路线 ≥ 85%（不管识别对错）。每个失败都归因为 `rule_miss` 或 `asr_miss`。

第一轮（旧规则）中文 59%、英文 SenseVoice 66%：规则假设识别结果带标点、拼写正确，真实输出并非如此。按逐字识别输出修正的规则（每条都有原样回归测试和防误触用例）：

- 中文：句中没有标点的「换行」、识别成「换航 / 唤行」；列表开始后不带标点的「第二运行测试」（「第二天 / 第二次」等序数名词除外）；「第一点 / 第二条」不带逗号；粘在汉字间的「呃」；「插入此块」。
- 英文：「Sctch that / Scch thought / Scrach that」这类残片（没有英文单词是 sc + 纯辅音，也没有「scratch 少一个字母」的词）；没有句号但下一句首字母大写时的撤回；「first」后无逗号但后面有真正的「second,」；「number3」「number 2」数字形式；「openParon / open_paran / Close Peran / openPan / open. Pern / closePerren」等括号误听；句末「press En」；Qwen3 的 Title Case（「Snake Case Max Retry Count」）、粘连的「CamelCaseDisplayName」和自己补的问号。

回放还抓到两个跟规则无关的真 bug 和一处打分归因问题，都已修：

- **Qwen3 整句丢失**：Qwen3 偶尔在正文前吐出一个多余的词和换行（`提纲\nlanguage English<asr_text>Is the cache warm?`）。sherpa-onnx 的 JSON 输出不转义控制字符，Rust 封装解析失败返回 `None`，这句听写直接报错丢掉。修法：vendored 封装在解析前转义字符串里的控制字符（标注为 VocalCode patch）；Qwen3 路线只保留最后一个 `<asr_text>` 之后的文字，不再把提示头打给用户。
- **es/fr/de 缺 32 条界面文字**（日历、改写草稿板）：付费版仓库的合约测试发现，社区版没有这条测试；已补译并加上同样的测试。
- 打分器曾把「Snippet Sign.」（识别器把 signature 听成 Sign）和 Qwen3 幻觉出的「提纲」算成规则漏判；归因改为要求片段名也被听到、整句基本听对。

### 补充的三类证据：中英混说、没说话、长口述

1.4.0 的语料只有短句、只有人在说话，所以下面三种情况从来没被测过：

- **中英混说**（`zh-cs-*`，9 条）：中文开发者最常见的说法。5 条普通口述（功能名 `code_switch`，如「跑一下 npm run build 看看有没有报错。」「这个 API 的 response 里少了一个 user ID 字段。」「明天和 product manager 对一下 roadmap。」），4 条跟换行、另起一段、删掉上一句、列表搭在一起。期望写的是正确行为：英文词都在（`terms`，不分大小写、不管中间有没有空格，「road map」算 roadmap，「user IDD」不算 user ID）；中文句子用全角标点（`cjk_punct`：含汉字的一行里，`, . ! ? ; :` 只要不在 `index.html`、`1.5`、`3:30` 这种词内部、也不是行首的「1. 」列表序号，就算错）。识别原文是全角、输出变成半角的，算 `rule_miss`，也就是我们文本管线的 bug，进 G3。英文词听没听到是模型本身的事，这类用例单独报告，不计入 G4。每条路线报告英文词召回率、全角标点通过率和混合错误率（MER：一个汉字或一个英文词算一个单位）。
- **没说话**（`ns-*`，7 段，每段 1–3 秒）：风扇（远处 -52 dBFS、近处 -40 dBFS）、键盘敲击（-40 dBFS，峰值约 -11 dBFS）、咖啡馆人声（6 个合成声音倒放后叠在一起，听不出任何词，-40 dBFS）、粉红噪声（-46 / -36 dBFS）、安静房间的底噪（-66 dBFS）。全部由 `generate.py` 用标准库合成，不用任何录音。语言标为 `any`，所有路线都会回放；每段在语音门开、关两种状态下各跑一遍规则全开和全关（出厂默认是关）。**G5**：什么都不许打，也不许按回车；有哪个状态没跑到，同样算失败。
- **长口述**（`en-long-30/60/90`、`zh-long-30/60/90`）：同一个声音（Andrew / 晓晓）把一份周报逐句念完，每句去掉首尾静音再拼起来，所有停顿都压到 180 ms 以内。应用要遇到 240 ms 的停顿才会切段，所以 30/60/90 秒整段只解码一次。`pink46` 变体再叠一层 -46 dBFS 的粉红噪声，高于停顿判定的安静阈值，同样切不开。**G6**：输出不能为空，对拼接原文的 WER/CER 不超过 10%，不能出现单独的 `language`；该语言的长口述用例没跑到也算失败。

新增的运行方式：路线加后缀 `+gate-off`（如 `zh:sensevoice+gate-off`）表示整条路线关掉语音门跑；`VOCALCODE_VOICE_ONLY` 和 `run.py --only=` 接受逗号分隔的多个用例 id 片段。

这些失败正是要补上的证据，由别的分支来修：

- **标点归一化**（G3 zh）：`Normalizer` 只要看到全角标点前面是 ASCII 字母，就把它换成半角，于是「roadmap。」变成「roadmap.」，「build，看看」变成「build, 看看」。修好之后 G3 zh 应当回到 0 次。
- **没说话时的幻觉**（G5）：出厂默认关着语音门，SenseVoice 会把风扇声、键盘声、底噪听成「。」「我。」（中文路线）或韩文「그.」「아.」（英文路线）。语音门打开时能拦住其中 6 种，但倒放的人声被 Silero 判成有人说话，两条 SenseVoice 路线分别打出「可对有公司。」和「Because also.」。Parakeet 在所有情况下都什么也没打。
- **Qwen3 长音频**（G6 en Qwen3）：sherpa-onnx 的 Qwen3-ASR 解码器 `max_total_len` 只有 512，超过约 20 秒的音频会被截掉一部分音频占位符。30 秒只转写出前面四分之三（WER 26%，句子断在「They still need a design」）；60 和 90 秒整段只剩一个「Language」或「提」（100%）。平时在 240 ms 停顿处切段，碰不到这个上限；但一口气说下去不停顿，或者底噪高过安静阈值时，整段一次送进去，就会丢一截甚至全丢。

英文词召回偏低（npm run build 0/12、user ID 0/12、design team 0/12、main 1/12）主要是 Edge 中文声音读英文带口音、SenseVoice 又听不出来，属于模型的上限，只报告、不设闸门。

## 已知限制 / 没做的

- 规则是确定性的：说法必须接近列出的短语；识别错一个字就不会触发。Wispr 那种「actually 3 → 改成 3」的语义纠正需要语言模型，没有做。
- 按应用风格只认程序名，浏览器里的 Slack / Gmail 算同一个浏览器。
- 语音改写目前在草稿板里完成；「选中任意程序里的文字 + 快捷键 + 口述指令 + 原地替换」需要新的全局快捷键和跨程序替换，涉及输入钩子和焦点安全，未做。
- 静音只作用于默认播放设备上已经在播放的会话；听写开始后才开始播放的声音不会被静音。
- macOS：静音为空实现；其余规则是跨平台代码，由公开 CI 在 macOS 上编译和测试，但未在 Mac 真机上实测。
- 语音语料是合成语音（神经 TTS + 加噪/变速/低音量），能代表识别器的典型错误，但不等于真人、口音、远场麦克风和真实环境噪声。
