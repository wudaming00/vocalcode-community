# 胶囊边缘与微反馈 — 2026-09-23

用户反馈：极简布局可以，但边缘粗糙，交互仍不够灵动。本轮只调整桌面胶囊，不改音频、模型、会议或学习逻辑。

## 变化

- 同时开启 HWND 与 WebView 透明背景；HTML 背景透明，深色表面绘制在原生命中区域内侧一个 CSS 像素。圆角由 Chromium 抗锯齿后与桌面合成，原生区域继续限定点击范围，不以颜色键抠除黑色像素。
- 去掉硬亮描边，使用低对比内描边和非常轻的深色渐变；不增加外部大阴影或透明大窗口。
- 展开 220 ms / 收起 160 ms，改为归一化临界阻尼响应。开头不猛跳，末尾停稳；几何不超调，保持居中与鼠标锚点，快速反向仍从实际绘制位置继续。
- 悬停波形只有一次 320 ms 的轻微回弹，按钮采用短颜色过渡与按压缩放；空闲无循环装饰动画。移除小波形上多余的原生 tooltip。
- 保持 48 × 18 空闲、160 × 36 悬停、点击才展开更多；停止/取消录音不等待装饰动画，系统减少动态效果同时约束原生动画与 CSS。

## 原因与技术依据

此前硬边来自二值窗口区域与不透明背景的组合；仅调整 CSS 边框无法让最外缘与桌面进行 alpha 混合。这是基于现有实现和本机像素测试的判断。

采用项目锁定版本 Wry 的三层透明设置方式；上游示例同时配置窗口、WebView 和 HTML 的透明背景。[Wry 0.55.1 透明示例](https://raw.githubusercontent.com/tauri-apps/wry/wry-v0.55.1/examples/transparent.rs)

Windows 合成仍受 DWM 与子窗口 alpha 影响，因此没有只凭浏览器预览就宣称原生成功。Microsoft 也明确提醒子窗口/GDI 可能改变 alpha，需要实际验证。[Microsoft DWM 文档](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmenableblurbehindwindow)

## 验证

- 新增显式 opt-in 的 `control_bar_composition_smoke`。它短暂显示自己的纯色背景与生产胶囊，采样只限该背景覆盖的区域，不录音、不注入输入、不访问用户产品数据；结束后关闭测试窗口。普通测试和发行构建不会运行此探针。
- 本机三组可见合成检查通过：白背景展开、白背景紧凑、暗色背景展开。圆角外部像素与背景完全相同；左上角分别测到 21、13、13 个中间色像素，证明并非纯二值裁切。三次前台 HWND 均保持不变。
- 首次逐点屏幕采样很慢，期间前台状态发生变化，综合检查失败；探针改为一次性内存快照并防止退出前重复采样，后续稳定通过。暗色背景最初假设绝对黑，实际系统主题刷为深灰；改为比对测试背景的真实像素，不降低焦点或抗锯齿断言。
- 17 项胶囊纯函数、24 项胶囊前端、18 项隐藏原生布局、18 项真实 WebView 隔离 IPC 检查通过。
- 完整 Rust workspace all-targets 顺序运行：841 项通过、25 项忽略；全部前端 108 项通过，clippy `-D warnings` 通过。
- 浏览器预览检查静态外观与真实悬停/离开；动画预览仍为 UI-only，不能代替所有机器的原生帧时间测试。

## 限制

本机使用当前 Windows / WebView2 和约 127% 文字缩放。远程桌面、旧系统、不同显卡驱动、混合 DPI 仍需额外验证。没有宣称解决所有平台的边缘问题或保证 60 FPS；只替换本机测试，不发布。
