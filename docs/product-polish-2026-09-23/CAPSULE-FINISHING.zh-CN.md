# 小胶囊第二轮细节修整

本轮只优化 Windows 桌面小胶囊的视觉和交互边界；不改模型、录音、识别、文本注入或用户数据，不发布版本。

## 改动

- 原生窗口与网页背景使用同一组物理尺寸。实测 Windows 127% 文字缩放时，WebView2 的网页可视区取整会比 HWND 多出约 1–2 个物理像素；此前部分圆角会落到窗口外。现在由 HWND 尺寸 / 页面像素比例决定绘制范围。
- 圆角随展开高度连续变化，点击“更多”时菜单轻微淡入，关闭时保留过渡中的菜单外形；不增加常驻动画、不增加悬停菜单项。
- “状态未确认”的本地异常提示也沿用同一个原生圆角，避免它单独退回旧的 14 px 硬边样式。
- 录音音量条增加 100 ms 的高度过渡，避免低频状态刷新产生阶梯跳动。不改变音频处理速度。
- 按本轮后续反馈，正常录音和识别也保持 **48×18 的同一颗小胶囊**：录音为随音量变化的小波形，识别为轻微呼吸，不自动弹出 248×40 的 Listening / Working 横条。录音悬停才平滑露出停止、波形、取消；识别没有可用操作，因此悬停也不放大。不为小波形添加浏览器文字提示框。
- 旧录音提示条的隐藏不再依赖第二次配置锁成功：配置暂时被占用时，沿用小胶囊的真实显示状态；只要小胶囊可见，旧提示始终关闭。小胶囊关闭或不可用时仍保留原来的后备提示。
- 较宽的文字说明仅用于实际错误或“去历史找回文字”的可操作通知，不把录音、识别当成通知。
- 可用高度不足时，菜单改为限高滚动，避免高缩放下顶部菜单项落到窗口之外。重新打开回到顶部，普通状态刷新不打断滚动位置。
- 动作同时校验引擎代次和展示代次。收起、重新展开、导航、隐藏或录音状态变化后，旧页面的排队点击不能获得新的录音/导航权限。移动中的空闲按钮不具有动作权限；录音中的停止/取消不被动画延迟，但必须属于当前展开的展示代次。
- 保留原来的非激活窗口、前台输入焦点、防双击、录音 Stop/Cancel 和减少动态效果设置。

正常尺寸：收起/录音/识别 48×18，空闲或录音悬停 160×36，空闲时明确点击“更多”才显示 160×200 的菜单。以上为逻辑尺寸，系统缩放后会相应变大。

## 可重复验证

```powershell
cargo test --locked -p vocalcode-app --no-default-features control_bar::tests -- --test-threads=1
node --test packaging/release/test_control_bar_ui.mjs
cargo run --locked -p vocalcode-app --no-default-features --example control_bar_hidden_smoke
cargo run --locked -p vocalcode-app --no-default-features --example control_bar_ipc_smoke
cargo run --locked -p vocalcode-app --no-default-features --example control_bar_soak -- --seconds 120
```

长测可改为 `--seconds 1800`，范围为 60–7200 秒；时间太短、未遍历完整矩阵时测试会失败。该测试只创建一个不显示的窗口和独立临时 WebView 配置，不开启麦克风、不使用安装版配置、不注入文字。31 种状态/中间帧 × 6 档 WebView 缩放循环执行；检查实际绘制范围、可点击控件边界、受限高度下的菜单滚动和非激活样式。

资源输出只包含测试宿主本身，**不包含 WebView2 子进程**；不能将其视作完整应用内存或 CPU 数据。回调耗时也包含隐藏测试的轮询等待，不是屏幕帧率。临时配置目录留在测试输出给出的路径，便于诊断。

实际桌面合成检查需要明确的可见测试开关，短暂显示测试自有底板：

```powershell
cargo run --locked -p vocalcode-app --no-default-features --example control_bar_composition_smoke -- --visible-owned-backdrop
# 可分别追加 --compact、--dark；用 --recording 或 --processing 检查对应状态
```

它只采样自有底板覆盖的区域，检查四个透明角、四象限抗锯齿像素及前台焦点不变，不保存桌面截图。

## 本机检查记录

- Legacy 全工作区：850 项通过，25 项忽略；忽略项不是本轮验证完成的项目。
- Community 全工作区：849 项通过，25 项忽略（与 Legacy 存在条件编译测试差异）。
- 全部前端测试：113 项通过，包含小尺寸录音/识别、无大标签、无波形文字 tooltip，以及菜单滚动位置保持/重置。
- 原生布局：26 项通过，包含录音小胶囊、录音展开中间帧和两个受限高度滚动场景；原生按钮 IPC：26 项通过，包含录音收起后的旧 Stop / Cancel 拒绝。
- 明/暗底板 × 空闲/录音收起及展开、识别收起：10 项合成检查通过；四个角透明，四象限均有抗锯齿过渡，焦点未改变。另检查自有测试底板中的真实截图，未拍摄用户的桌面内容。
- Legacy 和 Community 两种编译配置均通过严格 Clippy 检查。
- 小图标版 30 分钟长测：4,704 次检查，25 轮完整 186 场景矩阵，零失败；最终构建另跑 180 秒，469 次检查、2 轮完整矩阵，零失败。
- 较早布局的 80 分钟长测：12,418 次检查、82 轮矩阵，零失败。该构建仍有原来的大录音状态条，不作为最新小图标行为的证据；中断的其他测试不算完整通过。
- 本地已替换兼容测试构建，保留 Legacy 1.3.1 的数据/更新身份，不发布、不增加版本号。替换时正常退出、备份旧 EXE 和数据；805 个受保护文件逐一核对未变化。重启后 Ready、原 SenseVoice、桌面控制条 On 均已确认，未启动录音或改写服务。
- 已安装程序另做 602 秒只读窗口观察：296 次采样，25 次观察到可见的 61×23 物理像素胶囊（本机文字缩放约 127%），没有双提示同时显示或无响应。其余主要为全屏应用下的正常待机隐藏；这不是实时听写端到端测试。

30 分钟小图标长测进行期间，删除了小波形的浏览器 tooltip，并整理了一处仅测试用的等价条件判断。这些不改变该隐藏布局矩阵的几何或交互测试路径；tooltip 缺失由独立前端检查验证，不称作经过鼠标悬停长测。最终构建另跑 180 秒的完整原生矩阵。网页浏览器预览当时不可用，视觉检查使用应用自己的 Windows WebView2 窗口。

长测资源采样另外包含测试宿主的 WebView2 子进程：预热后始终为相同的 8 个进程，私有提交量在约 205.5–231.6 MiB 间波动，总句柄数 3,664–3,687；宿主 GDI/USER 对象分别保持 4/12。此数据来自不断切换状态和缩放的独立隐藏测试窗口，不是完整 VocalCode 的常驻内存或空闲 CPU；有限时长不能证明永远没有内存泄漏。

## 限制

WebView 缩放压力测试不等于所有真实多屏 DPI、显卡、HDR 或远程桌面组合验证。隐藏窗口长测也不能证明可见动画的帧率。独立 WebView 仍有浏览器子进程的资源成本；本轮优先保留窗口隔离和输入安全，不做高风险渲染引擎重构。macOS 胶囊实现不在这次 Windows 修整范围内。
