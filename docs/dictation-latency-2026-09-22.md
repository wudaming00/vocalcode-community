# 长听写与渐进输入：本地优化验证

日期：2026-09-22（美国太平洋时间）。基线：Community 1.3.1 / `792c47f`。本轮只改本地源码和构建，不代表已发布、安装或完成真实输入框验收。

## 定位与改动

- 原普通听写在松键后才开始整段识别；现在累计约 8 秒后遇到可用停顿，提前异步识别已完成的音频段。仍在松键后统一执行清理、词典、片段命令并一次性输入，没有自动打开渐进输入开关。
- 原渐进输入虽然使用模型线程，调用者却阻塞等待结果；现在最多一个待完成请求，录音期间轮询领取。取消会丢弃该次接收端，迟到结果不进入下一次听写；普通模式的预处理失败会保留原音频，在松键后重试未处理部分。
- 停顿识别从“只看最后 400 ms、固定 RMS 0.015”改为寻找新音频中的完整约 240 ms 低能量区间。阈值相对当前扫描窗，不按语言/字词黑名单判断。持续说话不强制按固定时长切断。
- 扫描使用新音频加约 1 秒上下文，不在每次轮询时复制、重扫整个不断增长的录音；只有找到边界才取得完整待识别段。后台结果轮询为 80 ms，独立于 450 ms 的常规维护周期。
- 英文分段后句号、逗号等后面补空格，避免 `sentence.Next`；仍只追加，不回删已输入内容。
- Windows 长文本输入在同一次事务内复用 UI Automation COM 客户端，避免每 20 字重新初始化。**不缓存焦点观察结果**：每块仍检查前台窗口、UIA 原生窗口祖先/root、PID/runtime ID 和具体焦点元素。没有扩大文字块或改成默认剪贴板粘贴。
- 可选诊断增加 `asr_chunks`、`predecoded_audio_ms`、`finish_ms`、`injection_ms`。`asr_ms` 包含排队及结果领取等待，不能冒充纯模型时间。未开启诊断的用户不会因此被开启持久化。

## 真实模型回放（不是端到端输入框基准）

Windows / Ryzen 9 9950X3D / CPU 4 线程 / 本机 SenseVoice INT8。每语言使用已有公开 FLEURS 清单前 8 段，顺序拼接，段间加 400 ms 静音；预热 3 秒后各模式跑一遍。英文 `auto`，中文 `zh`。不使用用户私人录音，不访问麦克风、不自动输入文字。

| 音频 | 整段解码 | 普通预处理：段数 / 累计段解码 | 松键时剩余音频 / 尾段解码 | 渐进：段数 / 累计段解码 / 尾段 |
| --- | ---: | ---: | ---: | ---: |
| 英文 64.00 s | 1104.19 ms | 6 / 606.91 ms | 0.64 s / 17.03 ms | 17 / 725.82 ms / 16.76 ms |
| 中文 103.18 s | 2552.70 ms | 9 / 945.00 ms | 10.14 s / 96.96 ms | 26 / 1182.07 ms / 50.40 ms |

同一组样本、探针内相同规范化：英文 WER 为整段 18.44%、普通预处理 14.18%、渐进 18.44%；中文 CER 分别 6.06%、2.16%、3.90%。这是两个拼接样本，不构成统计置信区间、语言质量认证或通用准确率提升承诺。该探针的标点处理方法也与旧 9 月 6 日报告不同，不能跨报告直接排名。

工具：`vocalcode-platform/examples/assessment_long_dictation.rs`。

```powershell
cargo run -p vocalcode-platform --release --example assessment_long_dictation -- <sensevoice-dir> <public-audio-manifest.tsv> en 8 4
```

清单格式：`WAV 路径<TAB>参考文本`，WAV 为 16 kHz 单声道。该工具按 80 ms 音频步长重放边界检测，但不是按真实时间开麦，不模拟队列争用、噪声门、文本清理或 UI 写入。**尾段 17 ms 不等于用户松键到出字 17 ms**；运行时还可能有一个尚未完成的分段请求。

## Windows 只读焦点探针

显式运行 `windows_focus_client_reuse_probe`：20/20 焦点观察有效，未注入任何文本。10 次新建客户端每次约 6.37–24.27 ms；单客户端内 10 次完整重新观察约 4.87–9.00 ms。这只确认该桌面上的检查成本和复用路径可运行，不是完整文字输入速度；样本小且先后顺序固定，不能当对外倍数宣传。

## 仍需真实桌面测试

1. 连续无停顿、噪声掩盖停顿的长语音仍会积累较长尾段；当前不是逐词流式 ASR，不强行切单词。
2. 只有 SenseVoice 跑了本轮实际长音频；其他模型、口音、中英切换、真实麦克风、低功耗电脑和 macOS 还需测。
3. 分段减少上下文，可能改变标点、专名和跨停顿修正；当前小样本没变差，不保证所有语音均如此。
4. 已在运行的本地模型调用不能抢占。会议推理、低端设备、清理与最终焦点/插入仍可能带来等待；异步分段不等于整个输入过程都无阻塞。
5. 保留了现有“文字准备好时选择安全输入框，再在这次插入中锁定”的规则，没有新增光标位置/选区的跨段锁定。真实一边手动编辑一边渐进输入仍需专项验收，不能声称绝不会插到用户刚移动的光标处。
6. 本机现运行的旧安装为 1.3.0，配置 SenseVoice / zh、全局渐进关闭。本轮没有结束旧进程、改设置、迁移数据或替换安装；不能用旧进程验证这些源码修改。
